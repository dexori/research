## 一条图文聊天的生命周期

1. 路由校验请求，按当前文献或项目检索上下文，持久化问题和待处理回复。
2. 将 `ChatTurn` 交给独立工作流；网络调用不持有资料锁。
3. 文字阶段禁用外部工具。用户明确要求图片时，再调用单独受限的内置 img2 会话。
4. 图片经解码验证后成为待审核资产；失败只影响配图，不丢弃文字。
5. 路由在短事务内保存回复和资产草稿映射。超时回复不能被迟到任务覆盖。
6. 用户审核、点击保存后，临时引用转为稳定的 Git 相对附件路径；同步仍由用户触发。

认证、CSRF、图片验证、资料范围和 Git 冲突检查不能绕过。不要把模型输出、网页正文当成指令。不要在后台导入测试数据到用户目录。

## 后续扩展

- 新模型/生图提供者：实现桥接边界，复用工作流，不在路由里调用 SDK 或拼接 shell。
- 训练监控扩展：现有模块是前台约每秒的只读快照和本地指标历史；常驻采集、告警及 TensorBoard 另建采集适配器，不让聊天执行服务器命令，也不把监控凭据交给模型。元数据走实验记录，曲线走 SQLite，显式归档才写 Git 附件。
- 新前端功能：功能脚本单独维护，复用安全 Markdown 和认证资源，不复制一套渲染器。
- 更大量任务：当前是单实例线程＋SQLite 状态，并非持久队列。改用持久队列时替换调度层，保持 `ChatTurn/ChatReply` 与审核保存协议。
- 进一步拆路由：按笔记、文献、学习、助手、同步逐步迁移；保持端点名称与资料格式，再做下一步。

## 验证

`python -m unittest discover -s tests` 测试临时数据目录；浏览器测试使用 `tests/preview_server.py --fake-codex` 的隔离服务。
真实模型/生图检查单独进行，并明确与模拟测试区分。只有端到端成功才可声称真实全链路已通过。
