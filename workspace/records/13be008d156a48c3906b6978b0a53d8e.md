一、研究问题和假设
研究问题：
不同任务共享局部动作时，能否让模型共享相应表征；而在后续动作分岔时，又保留目标差异？

例如，“把杯子收进柜子”和“把杯子放到托盘上”可能共享接近、抓取、抬起，但后续移动和放置不同。
我们验证三个假设：
- H1：动作关系监督有效。 比单纯 Flow 微调更有利于跨任务迁移。
- H2：多尺度优于单尺度。 短期共享、长期区分，比只使用一个动作窗口更合理。
- H3：共享不会牺牲目标区分。 模型不会因为表征对齐而更容易选错对象或目的地。
这里不再把同义词成功率作为主要研究目标。
二、方法定位：哪些借用，哪些待验证？
CLASS 使用 DTW 比较未来动作序列，以相似度加权的正样本训练 Soft InfoNCE；原方法主要学习视觉表征，再进行策略学习。CLASS §4
我们的方案分两步：
1. 基础适配：把 CLASS 损失接到 π₀.₅ 的观察／语言条件表征上，与 Flow 联合训练。
2. 候选扩展：使用多个未来动作窗口，分别学习短期、中期和长期动作关系。
必须明确：
- CLASS 损失不是我们的创新。
- 接到 π₀.₅ 上是方法适配，不自动构成强贡献。
- 多尺度是否具有额外价值、是否足够新颖，都需要实验和进一步文献核查。
三、基模与训练范围
基模
优先选择通用 pi05_base 来源的 checkpoint，固定模型 revision、配置和权重哈希。官方区分了通用 base 与已经针对 LIBERO 微调的模型。OpenPI checkpoints
已有 LIBERO 微调模型可以用于调试接口，但不宜直接用来证明未见 LIBERO 任务泛化。
即使用通用 base，也不能保证它从未见过相关任务。因此正式表述应是：
“适配阶段留出任务上的迁移”，而不是未经验证的“完全未见任务零样本泛化”。

训练范围
主实验统一更新：
- VLM 语言骨干。
- 视觉编码器。
- Action Expert。
- 新增投影头。
保留原有连续动作生成，不加入 FAST 辅助损失，不加入技能分类器或硬路由。
若显存不足，调整所有实验共同使用的训练配置；不能只给某个实验冻结更多模块。
四、数据设计
4.1 第一轮：复用现有 LIBERO-Spatial
现有记录中的 Spatial 子集包含 432 个 episode、52,970 帧，可作为接口与方法试验的起点。
建议先按完整任务划分：
用途	建议任务数	作用
训练	6	学习共享动作
验证	2	选择超参数和 checkpoint
最终测试	2	测适配阶段留出任务


具体任务 ID 要在数据审查后固定，不能根据最终测试结果重新选。
不能随机拆帧。 同一 episode 的相邻帧高度相似，随机拆分容易造成泄漏。
同时，训练任务内部留出约 10% 的完整 episode，用于观察已见任务的泛化和离线表征质量。
4.2 正式研究：扩展任务种类
Spatial 的动作和任务结构比较集中，适合试验，但不足以支持“完全不同任务的技能复用”这一宽泛结论。
如果第一轮有效，再结合 Spatial、Object、Goal 中可用的数据：
- 按任务目标组合分组，去除跨 suite 的近重复任务。
- 约 70%／15%／15% 划分训练、验证、测试。
- 测试组合未参与适配，但其组成动作应在训练任务中出现过。
最终划分写入固定 manifest。
4.3 主实验不加语言增强
所有组先使用原始指令，不加入同义词增强。
后续可以把语言增强作为独立消融，但不能和主实验一起改变，否则又会混淆收益来源。
五、正式训练前的数据审查
这是第一个必须通过的检查点。
从不同任务的示范中，寻找：
1. 短期、中期、长期都相似的片段。
2. 短期相似、长期不同的片段。
3. 动作明显不同的片段。
其中第二类最重要。
人工检查约 100 组候选，结合视频和动作曲线判断：
- 近邻是不是主要来自静止动作？
- 是否只是同一 episode 的重复帧？
- 不同任务之间是否真的有可复用的运动？
- 10／25／50 步是否能覆盖行为分岔？
如果 50 步内几乎没有分岔，就不能硬说“长期表征区分目标”。 应调整窗口，或者先收窄为局部运动共享问题。
这一步还要确认动作字段的含义：增量控制、绝对目标位置、旋转表示、夹爪编码和实际 FPS。
六、模型与损失设计
6.1 表征从哪里取？
取 π₀.₅ 中观察、状态、指令融合后的 VLM prefix 表征，不取动作 suffix。
原因是 Flow suffix 输入包含加噪后的真值动作，可能让辅助任务“偷看答案”。
你当前的 [训练前向 (line 743)](/home/z/lerobot/src/lerobot/policies/pi05/modeling_pi05.py:743) 已计算 prefix 输出，可以在辅助训练开启时返回它。
第一版取最后一个有效 prompt token 的融合表征，再接小型投影头：
图像＋状态＋指令 → VLM → 原有上下文 → Action Expert → 连续动作
                       ├─ 10 步投影 z₁
                       ├─ 25 步投影 z₂
                       └─ 50 步投影 z₃
建议每个投影头为两层 MLP，输出 128 维并做 L2 归一化。
投影头只用于训练和表征分析；第一版不改变 Expert 输入、不增加推理路由。
6.2 动作距离
对于窗口长度 \(H\)，取实际有效动作序列：
\[
A_i^{H}=(a_t,\ldots,a_{t+H-1})
\]
使用 DTW 得到：
\[
d_{ij}^{H}=\operatorname{DTW}(\widetilde A_i^{H},\widetilde A_j^{H})
\]
其中 \(\widetilde A\) 是用于计算相似度的动作表示：
- 仅包含真实动作维度，不包含补齐到 32 维的零。
- 根据训练集统计量平衡平移、旋转和夹爪尺度。
- 保留幅度信息，不能把每条轨迹独立归一化成相同大小。
- 不跨 episode 拼接，不把 episode 尾部 padding 当真实动作。
动作距离的定标与模型原有动作归一化分开记录。
6.3 CLASS 权重和损失
每个尺度分别估计训练集距离分布，确定正样本分位阈值，并计算：
\[
w_{ij}^{H}
=
\begin{cases}
1-F_H(d_{ij}^{H}), & \text{有效正样本}\\
0, & \text{其他}
\end{cases}
\]
归一化得到 \(q_{ij}^{H}\)。模型对应的概率为：
\[
p_{ij}^{H}
=
\frac{\exp(\operatorname{cos}(z_i^{H},z_j^{H})/\tau)}
{\sum_{k\ne i}\exp(\operatorname{cos}(z_i^{H},z_k^{H})/\tau)}
\]
再计算：
\[
L_{\mathrm{CL}}^{H}
=
-\frac{1}{|\mathcal V_H|}
\sum_{i\in\mathcal V_H}\sum_{j\ne i}
q_{ij}^{H}\log p_{ij}^{H}
\]
自配对排除；没有有效正样本的 anchor 跳过，并记录其比例。
单尺度实验：
\[
L=L_{\mathrm{Flow}}+\lambda L_{\mathrm{CL}}^{25}
\]
多尺度实验：
\[
L=L_{\mathrm{Flow}}
+\frac{\lambda}{3}
\left(
L_{\mathrm{CL}}^{10}
+L_{\mathrm{CL}}^{25}
+L_{\mathrm{CL}}^{50}
\right)
\]
除以 3，避免多尺度组仅仅因为辅助损失整体更强而受益。
不同尺度使用不同投影头，避免一个向量同时被要求“短期接近、长期分开”。
七、采样和分布式训练
采样
先用动作摘要粗检索候选，再对候选计算 DTW，保存稀疏近邻索引，不建立全量两两距离矩阵。
每批包含跨示范的近邻及其他候选；候选尽量覆盖不同任务。
注意：
- 不把“不同任务”自动当负样本。
- 不把未计算过距离的近邻直接当负样本。
- 排除同一 episode 的紧邻重复帧。
- 所有实验使用相同采样策略。
多 GPU
最多使用你允许的 4 张卡，拟沿用物理卡 0、1、2、4；启动前重新检查占用。任务放入独立 tmux，不触碰其他作业。
建议目标全局 batch 为 32，但先做显存测试。
特别重要：
梯度累积扩大的是优化器有效 batch，不会自动扩大每次对比损失的候选池。

例如每卡 4、4 张卡：
- 每次前向的全局候选池是 16。
- 累积两次后，优化器 batch 是 32。
- 对比候选池仍不是 32。
多卡表征 gather 必须保留梯度，并测试损失与单卡参考结果一致。无有效 anchor 的卡也不能擅自跳过 collective。

主实验有效后再做
1. 软权重 vs 等权正样本：验证 graded similarity 的作用。
2. DTW vs 固定时间对齐距离：验证时间规整的作用。
3. 共享投影头 vs 分尺度投影头：检查尺度冲突。
4. 辅助梯度阻断到 VLM：只训练投影头，检查收益是否来自骨干更新。
5. 受限 vs 不受限 DTW：检查过度时间对齐是否伤害操作时序。
一次只改变一个因素，不同时堆效果预测、分类器、FAST 等模块。
九、训练设置与执行顺序
以下是起始设置，不是已验证的最优参数：
项目	起始方案
主训练预算	每组 30K optimizer updates
训练 seed	调试先 1 个；正式至少 3 个
精度	BF16，数值敏感的损失计算用 FP32
梯度检查点	开启
峰值学习率	从 1e-5 开始验证
warmup	1,000 updates
调度	固定 30K horizon 的 cosine
对比温度	起始 0.05
正样本阈值	起始最低距离约 2.5%，经验证集选择
辅助权重	小范围检查 0.01 / 0.03 / 0.1
保存	每 1K 保存；完整恢复状态定期保留


执行顺序：
1. 离线审查：确认动作近邻和分岔样本成立。
2. 单卡 smoke：几十步，检查损失、mask 和梯度。
3. 多卡 smoke：检查 gather、恢复、采样确定性。
4. 3K pilot：A/B/C，同一 seed，小规模验证。
5. 正式训练：通过检查后，再做多 seed 30K。
pilot 若作为正式训练的前段，必须从一开始保持 30K 调度 horizon；不能因为提前停在 3K 就缩短学习率计划。恢复时保留 optimizer、scheduler、RNG 和采样状态。
暂时不沿用之前 SmolVLA 的每步耗时估算 π₀.₅。先测稳定 200 步，再估算训练、DTW 预处理和评估各自的成本。
十、评估与成功标准
主要指标
主指标：适配阶段留出任务的完整闭环成功率。
建议：
- 开发评估：每任务约 10 个固定初始状态。
- 最终测试：每任务 50 个初始状态。
- 各模型使用相同状态和随机种子，进行配对比较。
- 最终测试集只在方案固定后使用。
必须同时报告
- 已见任务成功率：检查是否发生明显退化。
- 目标错误率：拿错对象、去错目的地、错误释放。
- 跨任务动作检索质量。
- “短期相似、长期不同”样本上的表征关系。
- 训练／推理耗时和显存。
表征检索时排除同 episode 的重复帧，并同时检查投影后的表征和投影前的 VLM 表征，防止只是投影头拟合了监督。
少样本迁移
从训练完成的模型出发，在留出任务上分别给 5／10／20 个示范做适配。
每个模型使用相同示范、更新预算和超参数选择规则；训练示范与最终 rollout 状态分开。
如何判定结果？
- B 优于 A：支持 CLASS 辅助监督在此基模上的价值。
- C 优于 B：支持多尺度扩展。
- 检索改善但成功率不变：只能说明表征关系改善，不能宣称技能复用成功。
- 成功率提高但目标错误明显增加：共享机制存在代价，不能称兼顾目标保持。
- 多 seed 结果不稳定：需要增加证据，不能挑最好 seed 汇报。
结果按任务和训练 seed 分层报告，给出原始成功数、各 seed 均值／波动及配对差异；不把所有 episode 当作完全独立样本。
十一、工程验收与产物
实施时必须有以下测试：
- 辅助权重为零时，原有前向和动作输出保持一致。
- 改变真值动作、Flow 噪声和时间，prefix 表征不变。
- padding 不参与 DTW 或对比监督。
- 没有正样本时损失有限。
- 辅助梯度确实进入 VLM，而非只更新投影头。
- 单卡／多卡损失一致。
- 中断恢复不重置学习率或更换数据序列。
- 丢弃投影头后，推理输出不变。
每个实验保存：
- 模型、数据及代码版本。
- 任务和 episode 划分。
- 动作距离定标、CDF、阈值与近邻索引。
- 完整训练配置。
- 分开的 Flow／各尺度 CLASS 损失。
- 有效正样本比例、梯度范数、表征方差。
- 逐回合评估结果和失败视频。
最终研究主线保持简单：先证明单尺度 CLASS 有额外收益，再证明多尺度能更好地做到“局部动作共享、后续目标区分”。先过数据和机制检查，再投入完整训练。
