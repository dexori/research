# 研序 · Research Hub

一个在当前使用的电脑上运行的私人科研工作台。通过浏览器管理文献、实验、数据位置、研究想法和论文草稿，使用 GitHub 私有仓库同步资料。完成上传后，原来的电脑可以关机。

## 开始使用

需要 Python 3.10 或更新版本及 Git。

```bash
cd /home/z/research-hub
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python app.py
```

打开 http://127.0.0.1:8765 ，首次访问设置至少 10 个字符的密码。默认仅本机访问，使用 Waitress 运行，不开启调试模式。

## Linux 桌面双击打开

依赖安装好后，在平台目录运行一次 `.venv/bin/python desktop_launcher.py --install`。会在桌面与应用菜单添加「研序科研工作台」图标；如桌面提示不可信，右键选择「允许启动」。双击会后台启动平台并打开浏览器；已运行时只打开网页，不重复启动。关闭浏览器不停止后台服务，电脑重启后重新双击图标即可（没有设置开机自启动）。日志保存在 `data/desktop-server.log`。项目目录移动后需重新安装图标。新电脑拉取项目并安装依赖后，也可运行同一安装命令。

## 输入主题，整理学习知识

### 结构图与流程图

科研讨论、笔记正文、草稿审核和学习输出预览会自动把 fenced `mermaid` 代码块渲染为结构示意图。已有对话刷新即可显示，无需再次调用模型。支持常用流程图、时序图等；提供放大/缩放查看、SVG 下载及源码展开。图是根据文字整理的示意，不能冒充论文原图或已提取图片。Markdown 导出和 GitHub 同步仍保存源码，不修改原笔记。

使用本地固定版本 Mermaid Tiny 12.1.0（MIT），不请求 CDN。图表引擎在无同源权限、禁止网络访问的隔离 iframe 中运行，主页面只显示再次清理过的 SVG 图片；不开放工具执行、图中外链或配置指令。语法有误、过长或不支持的类型会显示说明并保留源码，不影响正文。Tiny 不支持原生 `mindmap` / `architecture-beta` 语法，可用 `flowchart` 表达科研架构；详见 [Mermaid 官方使用说明](https://mermaid.js.org/config/usage.html)。

「科研助手」「文献专属讨论」「学习整理」均有「模型 / 思考强度」选择器。默认跟随终端；可指定当前模型、选择名称预设或填写当前服务的自定义模型 ID。选择只在本浏览器记忆，不上传 GitHub、不修改 `config.toml`；点击「恢复跟随终端」可清除。切换只影响下一次调用，后台学习任务保留提交时的选择，关键词生成与知识卡整理使用同一组设置。学习过程面板显示该任务的请求设置（不是服务实际返回模型的认证）。

按 [OpenAI Docs 的单次配置覆盖方式](https://learn.chatgpt.com/docs/developer-settings?surface=cli)，仅传递 `--model` 与 `-c model_reasoning_effort=...`，不切换提供商、凭据、工具权限或搜索范围。模型名称预设不代表账号或自定义服务有使用权限；思考档位取决于模型和客户端。服务拒绝时明确报错，不自动换成其他模型。选择器不展示内部思考，也不保证调用成功。

在侧栏打开「学习整理」，输入 ACT 框架、π0 架构等主题，可选择关联研究项目。助手使用本机已有 Codex CLI 登录与模型配置，不需要另外填写 API Key，不修改终端全局配置。普通文献讨论仍关闭搜索并保留既有范围限制。

默认「平台检索 arXiv 原论文」：平台使用 [arXiv 公开文献查询接口](https://info.arxiv.org/help/api/user-manual.html) 检索、提取最多两篇论文正文，再把公开来源与读取范围交给终端整理，不调用终端的网页搜索工具。ACT、π0、π0.5、Flow matching 有原论文标题检索入口；其他主题先由终端转成英文关键词。必须成功提取至少一篇正文，全部读取失败时不生成卡片。单一来源或正文截断会注明；仅引用平台实际取得的来源。它是文献检索，不是全网搜索。

可选「Codex 网页搜索」：仅本次学习调用启用实时搜索，并要求观测到 CLI 网页搜索事件。当前终端的真实测试没有返回可用搜索记录，因此默认使用平台文献模式；自定义服务不一定支持搜索，详见 [OpenAI Docs 的搜索说明](https://learn.chatgpt.com/docs/web-search)。需要官方文档等非论文来源时可尝试此模式，但当前服务可用性尚未确认。

两种方式都不附带其他私有笔记，只向终端发送主题和公开来源，会使用终端服务额度。知识卡包含原理、公式、最小例子、自测问题与来源链接。检索记录、链接格式检查不代表对全部事实的自动认证。网络失败、超时、证据不足时明确报错，不以记忆冒充检索结果。

整理时，右侧「整理过程」展示真实阶段、候选论文、正文读取范围、时间戳和已等待时间。刷新网页会继续查看原任务，不会重复调用模型；历史任务可点击「查看过程」。展开「公开输出预览」可查看终端已返回的正文并渲染公式；有些终端仅在完成时返回正文，因此不保证逐字输出，不显示模型内部思考或原始工具日志，也不模拟进度百分比。进度与未审核预览只存本机。

生成后点击「审核并保存知识卡」，先核对内容与来源，再保存到「学习知识库」。支持标签搜索、知识分类和项目关联。已保存的卡片为 `workspace/records/` 内的 Markdown，点击 GitHub 同步后可在另一台电脑恢复。未审核草稿与任务历史只保存在本机，不随 Git 同步。关闭网页不取消任务，但关机或关闭平台会中断；中断任务最多九分钟后会显示错误，可以重新整理。原笔记不会自动被覆盖。

桌面启动器仅记录这台电脑的 Codex 程序/配置目录路径，不保存凭据，也不上传 GitHub。平台仍仅绑定 127.0.0.1，本机访问密码不变。

## 连接 GitHub，换电脑继续使用

1. 在 GitHub 创建一个自己的**私有空仓库**，例如 `research-hub`，不要预填 README 或其他文件。
2. 打开「GitHub 同步」，点击「登录 GitHub」。首次使用会下载并校验官方 GitHub CLI（需要网络），已有安装会复用。
   复制网页显示的一次性授权码，点击「前往 GitHub 授权」，在 GitHub 官网输入并确认；回来后会自动显示登录账号。超时可点击重新登录，不需要助手或手填令牌。
3. 填写 HTTPS 仓库地址（例如 `https://github.com/你的用户名/research-hub.git`）及分支（通常为 `main`），保存设置。网页登录适用于 HTTPS；SSH 地址仍需要独立配置密钥。
4. 点击「同步到 GitHub」，成功后代码、笔记和附件就在仓库中，可以关闭当前电脑。

新电脑的无终端授权流程：安装 Python 和 Git，在浏览器登录 GitHub，打开自己的私有仓库，选择 **Code → Download ZIP** 并解压。进入解压后的项目目录，运行下面的虚拟环境和启动命令（跳过 `git clone`）。打开网页设置本机访问密码，在「GitHub 同步」点击登录、确认授权，填写同一个 HTTPS 仓库地址并同步。下载包中的笔记会自动恢复；第一次同步会建立本地 Git 仓库并合并远端历史。

如果已经配置了 Git 访问凭据，也可以克隆同一仓库：

```bash
git clone https://github.com/你的用户名/research-hub.git
cd research-hub
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python app.py
```

打开 http://127.0.0.1:8765 ，在新电脑设置本机访问密码。平台会自动从仓库恢复笔记、项目、实验记录与附件。原电脑无需在线。

Windows PowerShell 可使用：

```bash
git clone https://github.com/你的用户名/research-hub.git
cd research-hub
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe app.py
```

两边每天使用的流程是：**开始时同步 → 网页编辑并保存 → 离开前再次同步**。看到同步成功再关机。网页保存立即写入本机文件，但不会自动联网上传；离线可工作，联网后重试同步。

GitHub HTTPS 同步遇到临时 TLS 握手失败、连接重置或超时时，会有限次数重试；还会尝试当前电脑环境中已有的 HTTPS / SOCKS 代理，并在本次运行中优先复用成功连接方式。不会自动绕过已配置代理，不修改全局 Git 设置，不关闭证书验证。每次拉取或推送的重试总时限为 90 秒，仍失败会明确提示保留本机资料。认证失败、证书错误或分支冲突不会被当作网络问题重试。

已经克隆过的电脑也可以手动拉取：

```bash
git pull --ff-only
.venv/bin/python app.py
```

手动拉取后，刷新网页即可载入新内容。存在本机未上传的修改时，优先使用平台同步按钮，它会先保留本机提交，再合并远端变化。请勿直接用强制覆盖或重置工作区的方式更新资料。

不同记录的修改可以合并；同一份笔记产生冲突时，页面会显示两个版本。可选择「保留两份」，另一个版本会成为新记录，包括其附件。处理完冲突后再次同步上传。临时的原版本副本还会留在本机 `data/sync-conflicts/`。

## 公式与终端草稿导入

公式支持行内 `$z_t = f_\theta(o_t)$`、`\(z_t = f_\theta(o_t)\)`，以及独立公式 `$$...$$`、`\[...\]`。公式块前后留空行，例如：

```markdown
## 表示学习假设

行内公式：$z_t = f_\theta(o_t)$。

$$
L = -\log \frac{\exp(s^+/\tau)}{\sum_j \exp(s_j/\tau)}
$$
```

显示层也兼容终端粘贴时多转义的 `\\(H\\)`，以及没有前后空行、紧贴正文的 `\[...\]` / `$$...$$` 公式块。只保护并规范化渲染用的分隔符，不改写数据库、Markdown 原文或公式内部的反斜杠；`cases`、矩阵等的 `\\` 换行保持不变。规范排版仍建议在公式块前后留空行。

代码块和行内代码中的公式保持原样；写美元符号可使用 `\$`。错误或不支持的 LaTeX 会保留原文，鼠标悬停显示提示，不影响整页。数学资源和字体随代码仓库携带，不从外部 CDN 加载；渲染禁用可信 HTML/链接命令、限制宏展开次数。为了公式排版，仅允许元素样式属性，脚本仍仅允许本机同源资源。

在终端讨论结束后，让助手把**你选中的总结**保存为 UTF-8 Markdown 文件。然后从平台目录执行：

```bash
.venv/bin/python research_cli.py import "讨论草稿.md" --kind idea --open

# 可选：指定标题和标签
.venv/bin/python research_cli.py import "文献笔记.md" --kind paper --title "DTW 阅读笔记" --tags "DTW, VLA"

# 查看项目 ID；导入时可添加 --project 完整项目ID
.venv/bin/python research_cli.py projects
```

`--kind` 可以是 `idea`、`paper`、`experiment`、`writing`、`dataset`、`project`。不填标题时取第一个一级标题或文件名。命令只读取指定文件，不扫描 Codex 配置、凭据或其他聊天记录，不调用模型，不直接写 SQLite 或正式资料。默认只打印本机审核页链接；`--open` 才会打开浏览器。平台没有启动时也能暂存，之后启动并打开「终端导入」查看。

网页中可上传 `.md`、`.markdown`、`.txt` 或粘贴总结；每份最多 2 MB，内容按原文导入，不解析执行其中的命令、脚本或 frontmatter。审核页可以切换类型、选择项目、编辑正文；**点击保存才创建一条新记录**。切换类型会重新载入原始草稿，已编辑内容请先保存。导入不覆盖已有记录；同一个草稿重复保存会打开已导入记录，不重复创建。

Windows 使用 `.venv\Scripts\python.exe research_cli.py ...`。自定义端口可在子命令前加 `--port 8766`；自定义缓存须通过 `RESEARCH_DATA_DIR` 或 `--data-dir` 与运行中的平台保持一致。

待审核草稿在 `data/import-drafts/`，不会进入 GitHub；保存后的正式记录按现有流程同步。完整 ZIP 备份包含草稿箱和导入状态，恢复时一并把 `import-drafts/` 复制到新数据目录。本次只增加草稿导入，不会把终端整段会话自动同步成网页聊天历史。

## 科研助手：沿用 codex2 终端

打开左侧「科研助手」，选择项目并提问。一般讨论按关键词筛选最多 6 条记录；文献页则直接提供独立讨论区，默认只读取本篇笔记及已提取的原文，不检索其他文献。刷新或续聊仍保留该范围，历史讨论按文献区分。

论文链接不再只是书签：在文献页点击「读取论文链接」，或首次发送问题时自动尝试读取公开 HTTPS 链接。arXiv abs/html 链接自动定位 PDF，OpenReview forum 链接也会定位 PDF；其他站点支持直接 PDF、citation_pdf_url 或包含明确正文结构的 HTML。付费墙、仅摘要页面、扫描 PDF、读取失败会明确提示，不冒充已读。上传的 PDF 可单独点击读取。最多下载 20 MB，解析有独立进程、时间/内存限制；不执行页面脚本，逐跳限制公开 HTTPS 地址并固定已验证 IP，拒绝本机/内网地址。不绕过付费墙。若确需 HTTP 代理，可由本机管理员设置 RESEARCH_PAPER_PROXY；不由页面指定代理，不关闭 TLS 验证。

提取文本单独保存为 JSON 附件，随 workspace/ 与 GitHub 同步，不覆盖笔记。缓存绑定当前论文链接；修改链接后需重新读取。单篇最多提取 180,000 字符；专属讨论每次最多发送前 65,000 字符，一般检索的原文总预算 20,000 字符。截断会标记，模型必须说明收到的范围；图表、复杂公式与扫描图片不能视为已识别。答案下方显示实际传入原文字符数。

本模式不需要在网页输入 API Key，但需要在**运行平台的这台电脑**安装、登录 Codex CLI，并能正常在终端对话。使用既有的终端配置、服务提供方、模型和额度，仍需要网络，额度与费用由该终端配置决定。默认优先使用 `~/.codex-gpt2`（即当前电脑的 `codex2` 配置），不存在时使用 `~/.codex`。可通过 `RESEARCH_CODEX_HOME` 指定既有配置目录、`RESEARCH_CODEX_BIN` 指定 Codex 可执行文件的绝对路径；不会执行 shell 函数或加载 `.zshrc`。新电脑仍需自行安装和登录 Codex，GitHub 不同步这些凭据。

网页的「换电脑：如何连接本机 Codex」有完整指引及登录检查按钮。按 [OpenAI Docs 安装说明](https://developers.openai.com/codex/cli)安装 CLI，在本机运行 `codex login`，然后运行 `codex` 确认能对话，再重启平台。设备码登录方式见 [官方登录文档](https://developers.openai.com/codex/auth)。登录检查只调用 `codex login status`，不消耗模型额度、不回传原始输出，不等于验证服务连通性。自定义服务需在新电脑单独配置，不要把凭据上传 GitHub。

每次调用建立独立的临时会话，不继承本次与助手的聊天或其他 Codex 会话。命令参数固定，问题通过标准输入传递；采用只读沙箱，禁用命令执行、浏览器、插件、MCP 和多代理能力，只讨论传入的笔记，不运行实验或直接修改科研资料。每次最多等待 3 分钟，同一实例同一时间调用一个 Codex；等待时可在其他页面继续编辑。

网页聊天会立即返回任务，随后显示实际调用阶段、用时、公开回复与处理日志；刷新可继续查看。
仅展示助手公开说明，不展示内部推理或原始工具/错误输出，不模拟思考步骤。部分终端服务只在完成时返回正文，不能保证逐字流式；等待期间仍显示真实状态与计时。普通文献讨论不开放生图、命令或外部工具。

## 图文学习知识卡

在「学习整理」输入 ACT、π0 等主题，可勾选「使用 Codex 内置 img2 生成一张教学配图」。
流程为：检索公开论文并提取正文 → 生成知识卡 → 检查来源 → 单独调用 img2 → 图文审核 → 保存 → 手动 GitHub 同步。
目录、摘要、重点与误区卡片、公式、图片图注会自动排版；编辑页有随输入更新的图文预览。点击图片可放大或下载。

生图使用既有 Codex 登录与额度，不要求额外 API Key。需要当前 Codex CLI/服务支持内置 `image_generation` 和命名空间工具；仅功能开关开启或安装技能不能证明账号可用。
本机 Codex 0.160.1 已实测内置工具及平台桥接生成有效 PNG。图片调用为独立临时只读会话，只提供本篇知识卡正文，仍禁用 shell、插件、外部 MCP、多代理及搜索，不通过 API 脚本兜底。
Codex exec JSONL 可能省略命名空间工具的图片事件；平台只接收实际新生成、位于所选配置 `generated_images/` 内且可解码验证的静态 PNG/JPEG/WebP，不接受成功声明、旧图片、符号链接或任意本机路径。
每次只生成一张图，消耗生图额度（一般高于文字对话）。配图失败、超时、额度不足会保留文字草稿。审核页支持取消图片或重新生成另一份草稿，不覆盖原版。

AI 插图标注为教学示意，不冒充论文原图或实验结果；模块关系、标签和事实仍须人工核验。复杂公式保持为可编辑文字，不烘焙进图中。
未审核图片与提示词保存在本机 `data/draft-assets/` 与草稿清单中；保存时仅复制用户勾选且正文引用的图片，并将临时链接转换为 `../attachments/<稳定ID>/attachment.png` 等相对路径。
此后图片、笔记和附件清单随 GitHub 同步，另一台电脑可恢复并显示，不依赖旧电脑路径。不会自动上传草稿，也不会为生图自动上传其他私人资料。
图片展示只允许平台本地认证路径，禁止外部图片追踪、SVG/HTML 和事件属性；原有 Markdown 安全过滤与 CSP 保持开启。

回答下方「审核并保存为笔记」先打开编辑页，**只有点击编辑页的保存按钮才会写入资料**。可以新建想法、文献笔记、实验计划或论文草稿，也可以选择追加到本次引用的笔记。请核对文献引用、事实和指标；AI 草稿不等于验证过的结论。写入的笔记按已有 GitHub 流程同步。

聊天历史仅存在本机数据库，包含在完整 ZIP 备份中，但目前**不随 GitHub 同步**。换电脑需要保留的讨论结论，请保存为笔记后同步。Codex 登录文件、运行配置和临时目录不上传到资料仓库。网页的密码和 CSRF 保护同样适用于科研助手；不要把本机平台暴露到不可信网络。

## 存储、迁移与 GitHub

同步资料保存在工作区：

```text
research-hub/
├── app.py、templates/、static/       # 网页应用代码
├── workspace/
│   ├── records/<记录ID>.md          # 正文 + 可恢复的元信息
│   └── attachments/<附件ID>/        # PDF、图片、CSV 等原始文件
└── data/                            # 仅本机：数据库、访问密码、会话密钥
```

`workspace/` 与应用代码一起进入 GitHub 私有仓库。每条记录都是独立 Markdown 文件，前面的 JSON 元信息保存标题、类型、项目关联、标签和附件信息，后面是可编辑的 Markdown 正文。请保留记录 ID 和元信息格式，直接删除文件不等同于归档；建议在网页归档资料。

本机数据保存在 `data/research.sqlite3` 和 `data/uploads/`，`data/session.key` 是登录签名密钥。`data/` 被 Git 忽略；密码、登录密钥和运行中的 SQLite 不会上传。每台电脑使用自己的本机访问密码。可用 `RESEARCH_DATA_DIR=/绝对路径` 更换本机缓存位置。

GitHub 凭据由官方 CLI 保存到本机系统凭据存储；系统没有可用的密钥环时，CLI 可能回退到自己的配置文件，请保护该电脑账号。网页只接收临时设备授权码和登录账号，不接收访问令牌。仅当前仓库设置 Git 凭据助手，不修改全局 Git 设置，不会同步凭据。浏览器的 GitHub 登录与平台的本机访问密码是两回事。

附件在仓库中使用稳定 ID 和通用文件名，原始文件名保存在笔记元信息中，下载时恢复原名。记录使用 LF 换行，附件禁止 Git 换行转换，以支持 Linux、macOS 和 Windows 之间切换。

完整备份包含 `research.sqlite3`、`records.json`、分类 Markdown、`attachments/`，以及存在时的 `import-drafts/` 草稿箱。恢复时先停止服务，准备一个**新的空数据目录**，复制备份中的 `research.sqlite3`，将 `attachments/` 改名为 `uploads/`，并复制 `import-drafts/`（如果有），设置 `RESEARCH_DATA_DIR` 指向新目录后启动。原访问密码继续有效，新的会话密钥会自动生成。

图文草稿备份还包含 `draft-assets/`，恢复时一并复制到新数据目录。未审核的草稿仍不通过 GitHub 同步。

第一次启动新版本会将已有本机笔记和附件迁移到 `workspace/`，保留原本的数据。完整备份仍可用于额外存档；新电脑正常使用只需克隆或拉取 Git 仓库。不要让两个实例同时操作同一个 SQLite 文件。

当前同步为网页按钮触发，不是每次保存自动上传。尚未接入 Zotero、DVC、训练作业监控、MLflow/WandB API 或 Overleaf；已有服务可以通过链接关联。论文 PDF、CSV 和小图片随仓库同步，每次附件上传上限 64 MB；大型数据集和权重通过存储路径或链接管理，没有配置 Git LFS。

## 运行与验证

```bash
# 修改监听端口
.venv/bin/python app.py --port 8766

# 修改密码，同时撤销现有登录
.venv/bin/python app.py --set-password

# 功能和访问保护测试
.venv/bin/python -m unittest discover -s tests -v
```

默认仅本机访问，符合「当前电脑打开网页、GitHub 同步资料」的工作方式。如果以后要在可信局域网共享，可先使用 `--set-password` 设置密码，再运行 `app.py --host 0.0.0.0`。服务器运行示例见 `research-hub.service.example`。此项目不会自行安装系统服务或修改防火墙。
